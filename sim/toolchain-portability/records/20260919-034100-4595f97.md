- **Record ID**: 20260919-034100-4595f97
- **Claim**: issue #254's fact (c) / DR-0025's **F3** -- for two `.options`
  cards naming the same key (`wnflag`), the **first** card wins and the
  later one is silently discarded, with no warning -- reproduces on ngspice
  majors other than the 46 `sim/tests/test_ngspice_options_precedence.py`
  pins it for. This is the simulator behaviour DR-0025's "a testbench
  manifest cannot override the pin" consequence and
  `sim/harness/runner.py`'s deck-composition ordering both depend on.
- **Netlist provenance**: N/A -- toolchain-portability measurement (see
  `sim/toolchain-portability/README.md`). Two deck shapes: a PDK-free
  readback deck (a resistor divider plus an `echo` of the `wnflag` control
  variable) and the same pass-device bin-selection deck as F1/F2, each run
  with two `.options wnflag=` cards in both orders plus single-card
  controls.
- **Operating conditions**: N/A -- single `.op` points, no load network.
- **Corner matrix run**: N/A -- simulator behaviour, not a PVT-conditioned
  design claim. Measured once per toolchain build below.

- **Result**: **F3 HOLDS on every ngspice build measured** -- first-card
  precedence is not ngspice-46-specific:

  | build | `1` then `0`: cp readback | `0` then `1`: cp readback | `1` then `0`: bin | `0` then `1`: bin | discard warning printed? | F3 |
  |---|---|---|---|---|---|---|
  | `ngspice-46-pinned` | `1` | `0` | `pfet_03v3.12` | parse error | no | HOLDS |
  | `ngspice-46-fresh` | `1` | `0` | `pfet_03v3.12` | parse error | no | HOLDS |
  | `ngspice-47` | `1` | `0` | `pfet_03v3.12` | parse error | no | HOLDS |
  | `ngspice-42-apt` | `1` | `0` | `pfet_03v3.12` | parse error | no | HOLDS |

  Every build: the control variable reads back whichever value the **first**
  card set regardless of order, the bin-selection deck's outcome tracks that
  same first-card value exactly (a resolved bin when the first card is `1`,
  a hard parse error when it is `0`), and single-card controls in both
  values behave as expected. No build printed any diagnostic naming the
  discarded card. This is exactly the property `sim/harness/runner.py`
  relies on to make its own `.options wnflag=1` card authoritative ahead of
  anything a testbench manifest might try to add.

# Record 20260919-034500-4595f97

- **Record ID**: 20260919-034500-4595f97
- **Claim**: issue #254's numerical A/B -- a same-netlist, same-PDK,
  same-host comparison of `sim/loop-stability`'s loop-gain margins across
  ngspice majors, at and around the exact numerically-marginal operating
  point `sim/loop-stability/records/20260906-090647-3981d88.md` already used
  to characterize this repo's **accepted, already-documented** same-version
  (ngspice-46-vs-ngspice-46) build-to-build spread
  (`sim/README.md` -> "Reproducibility caveat: a version string is not a
  content fingerprint (#182)"). This record makes **no DR-0001 stability
  verdict** and **no claim about the design**: every arm is run with
  `sweep.py --no-write` specifically so a toolchain experiment does not mint
  a `sim/loop-stability` record (`sim/toolchain-portability/README.md`'s
  "What a record here may and may not conclude"). It answers one question
  only: does the ngspice-46 -> ngspice-47 major-version delta move loop-gain
  margins by more than the already-accepted same-version build spread?
- **Netlist provenance**: **schematic**, byte-identical across every arm --
  `design/netlist/ldo_core.spice` at this record's own git commit
  (`4595f971066a9b255684c4dc88991bb5cb36a218`), never regenerated or
  modified between arms.
- **Operating conditions**: `sim/loop-stability/testbench/sweep.py`'s full
  load/cap/ESR grid (6 load points x 3 output caps x 4 ESRs = 72 combinations)
  at the `ff` process corner, 125 degC, all three supply points in the
  standard +/-10% tolerance (2.97 / 3.30 / 3.63 V) = **216 loop-gain points
  per arm**. This corner/temperature is not an arbitrary choice: it is the
  corner `20260906-090647-3981d88.md`'s own diagnostic isolated as the
  largest same-version-build mover, and its exact operating point
  (`ff_125c_2.97v`, 1 mA, 0.33 uF, 0.2 ohm) is inside this record's grid.
- **Corner matrix run**: N/A in the `sim/README.md` PVT-matrix sense --
  this is a single-corner/single-temperature toolchain A/B, not a
  spec-verifying PVT sweep. See "Operating conditions" for the grid.
- **Statistical convention**: N/A -- a point-by-point delta between paired
  arms on an identical grid, not a distribution claim.

- **Result**: three arms, one host, one PDK, one DUT netlist, 216 loop-gain
  points each:

  | arm | ngspice | binary sha256 | points identical to `ngspice-46-pinned` (PM) | worst \|dPM\| | worst \|dGM\| |
  |---|---|---|---|---|---|
  | `ngspice-46-pinned` (reference) | `ngspice-46` | `c874869b...072931` | -- | -- | -- |
  | `ngspice-46-fresh` (independently built, same `configure` flags) | `ngspice-46` | `cec95020...484ff0` | **216/216** | **0.000000 deg** | **0.000000 dB** |
  | `ngspice-47` (issue #254's scope target) | `ngspice-47` | `ad57436c...2600b9e` | 201/216 | **1.972 deg** at `ff_125c_2.97v` / 1mA, 0.33uF, 0.2ohm | 0.908 dB at `ff_125c_2.97v` / 1mA, 1.0uF, 0.2ohm |

  Two independently-built ngspice-46 binaries (different sha256, same
  `./configure` flags) agree **bit-for-bit** on every one of the 216 points --
  the strongest-available control that this grid's own build-to-build noise
  floor, on this host, with these flags, is exactly zero. Against that
  control, ngspice-47 diverges from ngspice-46 at 15/216 points (9 at the
  2.97 V supply rail, 3 each at 3.30 V and 3.63 V; the remaining 201 points
  are bit-identical across all three arms), with a worst-case delta of
  **1.972 deg phase margin / 0.908 dB gain margin** -- the *same order of
  magnitude* as the already-accepted ~2 deg / ~1 dB same-version spread
  `20260906-090647-3981d88.md` measured and ruled non-design-causal. Notably,
  the single worst-|dPM| point this A/B found
  (`ff_125c_2.97v` / 1 mA / 0.33 uF / 0.2 ohm) is the **identical operating
  point** that record's own diagnostic isolated as the largest mover -- this
  is the same numerically marginal corner reasserting itself across a major
  version bump, not a new, unrelated sensitivity.

  **This does not, by itself, license moving the ngspice-46 pin** (out of
  scope per issue #254's own "Explicitly NOT in scope" section) -- it
  establishes that *if* the pin were moved, the expected numerical impact at
  this repo's most sensitive measured point is comparable to spread this
  repo has already measured and accepted as non-design-causal, not a new or
  larger category of drift. See DR-0027 for the full decision-record
  writeup and its explicit non-decision on the pin.

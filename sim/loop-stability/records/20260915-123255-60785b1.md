  verified against `spec/decision-records/DR-0024`'s 5x resize of
  `design/ldo_softstart.sch`'s `Css`/`Ch_ss`/`Cr_ss` (merged in PR #223).
  **This record makes no new DR-0001 stability claim.** The DR-0001 verdict
  for this design (worst-corner PM/GM against the ratified 45 deg / 10 dB
  bar) is already, and remains, **FAIL** (tracked by issue #42/#51,
  unaffected by anything in this record), and this record neither alters
  nor supersedes any prior full-matrix record's own PASS/FAIL verdict.
- **Netlist provenance**: `design/netlist/ldo_core.spice`, current head
  (commit `60785b1`, the merged DR-0024 resize) — same DUT as
  `sim/soft-start/records/20260915-103035-18f664f.md` and
  `sim/quiescent-current/records/20260915-115046-60785b1.md`.
- **Result, up front**: **the resize moves no loop-gain number.** Three
  corners were re-run at full resolution against BOTH the resized netlist
  (`60785b1`) and the immediately-prior, pre-resize netlist
  (`8517f0c`, PR #223's own parent commit, i.e. the design exactly as issue
  #212 found it), on the same host in the same session:

  | corner | pre-resize (`8517f0c`) worst PM / GM | post-resize (`60785b1`) worst PM / GM | delta |
  |---|---|---|---|
  | `tt_27c_2.97v` | 6.92 deg / 1.33 dB | 6.92 deg / 1.33 dB | 0 |
  | `tt_27c_3.30v` | 5.86 deg / 1.22 dB | 5.86 deg / 1.22 dB | 0 |
  | `tt_27c_3.63v` | 5.09 deg / 1.13 dB | 5.09 deg / 1.13 dB | 0 |

  Bit-for-bit identical at every one of the three corners checked (216
  loop-gain points each), which is exactly what `spec/decision-records/
  DR-0024`'s own "unaffected by construction" argument predicts: `Css`,
  `Ch_ss` and `Cr_ss` are capacitors on nodes (`SSR`, `HG`, `SD`) that carry
  no DC current and are opens at the AC operating point this bench solves
  around — resizing them cannot move a small-signal loop-gain result unless
  it also changes which DC branch the Newton solve lands on (see next
  finding). This record confirms that prediction empirically rather than
  leaving it as an unverified argument, per this repo's "no claim without a
  testbench" convention.

  For context, these three corners' worst-PM/GM values also differ from the
  figures in the last full-matrix head record
  (`sim/loop-stability/records/20260906-071437-fff0bf0.md`: `tt_27c_3.30v`
  reads 5.12 deg / 1.05 dB there, not 5.86 / 1.22). That difference is
  **not** attributable to this record's resize either — `fff0bf0` predates
  issue #189/#191's replacement of the soft-start clamp with FB current
  injection, so its DUT netlist is a different design (the #38/#43 clamp
  topology, not the #189 injection topology this record's DUT and
  `8517f0c` both share). `sim/loop-stability`'s full-matrix bench has not
  been re-run against the post-#189/#191 design before this record; that
  gap predates and is independent of issue #212's own scope.

- **A second finding, also pre-existing and also not this record's to
  fix**: a full 4536-point sweep against the resized netlist
  (`60785b1`, `-j 14`, default `--corners`/`--temps`) voids at
  `ff_125c_3.63v` — the harness's own convention refuses to write a record
  when any corner fails to land on the regulating DC branch (`sim/
  loop-stability/testbench/sweep.py`'s `.nodeset`-seeded retry, exhausted;
  "72/72 points did not settle on the regulating DC solution"). Re-running
  the **identical corner** against the **pre-resize** netlist (`8517f0c`)
  reproduces the same failure signature: every one of that corner's 72
  `.meas` extractions throws `out of interval` (96 total error lines across
  the corner's log, i.e. every named measure at every load/cap/ESR point),
  because the AC solve's own cold-started operating-point search does not
  reach the regulating branch there either. Same corner, same qualitative
  failure, on both netlists — this is the already-tracked issue #191
  acquisition-transient/settled-leakage regression (the same corner,
  `ff`/`125 C`/`3.63 V`, that `sim/quiescent-current/records/
  20260915-115046-60785b1.md` and its superseded predecessor both report as
  the one `vout_full_v` FAIL below 1.7 V, i.e. a genuinely marginal DC
  operating point independent of this bench), not something this resize
  introduces. It is why neither this record nor any record since #189/#191
  landed has minted a fresh, clean 4536-point `sim/loop-stability` record;
  closing it is issue #191's scope, not #212's.

- **Conclusion for issue #212's acceptance criterion**: loop-stability is
  unaffected by DR-0024's ramp/delay-capacitor resize, confirmed directly

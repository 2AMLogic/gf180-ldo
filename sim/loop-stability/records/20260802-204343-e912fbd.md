## Result

### 1. No point changes verdict, on either bar

| | baseline `db620a6` (`dec 50`) | head `e912fbd` (`dec 400`) | delta |
|---|---|---|---|
| DR-0001 PASS (PM ≥ 45° **and** GM ≥ 10 dB) | 1332 / 4536 | 1332 / 4536 | **0** |
| PASS → FAIL | | | **0** |
| FAIL → PASS | | | **0** |
| DR-0008 `resurgence_db` > 0 dB | 0 / 4536 | 0 / 4536 | **0** |

**Issue #58's acceptance question — "does any point that the head record
calls PASS change verdict under a finer grid?" — is answered NO, at all 4536
points, on both bars.** The result the repository has been reporting at
`dec 50` is not an artifact of that resolution.

That is the answer for **this netlist at this design state**, and it is not
transferable. It says the loop as compensated at `e912fbd` has no feature
sharp enough for `dec 50` to have mangled; it does not say `dec 50` is
adequate in general, and the self-test the policy is validated against
(`selftest.py`, third reference loop) is a constructed counterexample where
`dec 50` reports a clean **false PASS** on a bar that has no slack in it.
The point of raising the resolution is that there was previously no way to
know which of those two situations the design was in without doing exactly
this run.

### 2. How far the numbers moved

Computed over all 4536 matched points:

| quantity | median | p99 | max | where the max is |
|---|---|---|---|---|
| \|Δ phase margin\| | 0.000° | 0.030° | **0.040°** | `ff_125c_2.97v` / 10 mA / 1 µF / 0.5 Ω |
| \|Δ gain margin\| | 0.000 dB | 0.010 dB | **3.300 dB** | `ss_-40c_3.63v` / 0.1 mA / 4.7 µF / 1 mΩ |
| \|Δ crossover\| | 0.010 % | 0.034 % | **0.055 %** | `res_ff_125c_3.30v` / 1 mA / 4.7 µF / 0.5 Ω |
| Δ `resurgence_db` | +0.879 dB | +2.021 dB | **+2.362 dB** | `ff_125c_2.97v` / 50 mA / 0.33 µF / 1 mΩ |

Phase margin and crossover are essentially invariant: **no point** moves more
than 0.04° or 0.055 %. Gain margin is invariant at all but **five** points
(|Δ| > 0.01 dB) and materially at exactly **one**. `resurgence_db` moves
everywhere, and for a reason that is not physical — see §4.

### 3. The one gain-margin move, and whether it is the failure mode #58 describes

It is.

`ss_-40c_3.63v`, 0.1 mA / 4.7 µF / 1 mΩ:

| | `dec 50` | `dec 400` |
|---|---|---|
| crossover `f_0` | 14 269.4 Hz | 14 265.7 Hz |
| phase margin | 78.55° | 78.55° |
| **first −180° crossing `f_180`** | **2.423 MHz** | **871 kHz** |
| **gain margin** | **45.68 dB** | **42.38 dB** |

The finer grid does not read the *same* crossing more accurately. It finds an
**earlier −180° crossing, 2.8× lower in frequency, that the `dec 50` grid
stepped over entirely** — which is precisely the mechanism issue #58's title
names, observed on the shipping netlist rather than on a constructed
example.

**Is the 871 kHz crossing real?** Re-probed at three resolutions
(`corners/20260802-204343-e912fbd/`, one configuration, phase scanned over
0.6–3 MHz):

| `ac dec` | −180° falling crossings found in 0.6–3 MHz |
|---|---|
| 50 | 1 — between 2.399 and 2.512 MHz |
| 400 | 2 — at **871.0 kHz** (φ = −180.00°, \|T\| = −42.4 dB) and 2.41–2.43 MHz |
| 4000 | 2 — at **871.0 kHz** (φ = −180.00°, \|T\| = −42.4 dB) and 2.422–2.424 MHz |

`dec 400` and `dec 4000` agree on the 871 kHz crossing to the digit printed,
so the `dec 400` reading is converged and the `dec 50` reading is the wrong
one. The feature is a **grazing tangency** — the phase touches −180.00° and
turns back rather than sweeping through — which is why it is so easy for a
coarse grid to miss and why the two neighbouring `dec 50` samples straddle it
without either falling below −180°.

**Consequence at this design state: none.** Both readings sit 32 dB above
DR-0001's 10 dB bar, the phase margin is untouched, and the point passes
either way. The value of the observation is not that it changed a verdict —
it did not — but that the mechanism is demonstrably present in this loop, at
a point that happens to have 32 dB of margin to absorb it. There is no
argument available that it could only ever land somewhere harmless.

### 4. `resurgence_db` moves at every point, and that is a metric artifact, not physics

`resurgence_db` (issue #59, DR-0008's precondition check) is defined as the
largest `|T|` in dB anywhere above the first 0 dB crossing, scanned from
**one AC-grid step** above that crossing — `f_0 × 10^(1/AC_DEC)` — so the
crossing itself, where `|T|` is 0 dB by definition, is not reported as its own
resurgence.

That start offset is tied to the resolution. At `dec 50` the scan begins
4.71 % above `f_0`; at `dec 400`, 0.577 % above it. So the finer grid samples
`|T|` closer to the crossing, where it is closer to 0 dB, and reports a
larger number for the *same* loop:

- `resurgence_db` moves **positive at 4536 of 4536 points**, by +0.061 to
  +2.362 dB.
- The worst point in the matrix moves from **−0.0746 dB** (`dec 50`) to
  **−0.0086 dB** (`dec 400`) — `ff_125c_3.30v` / 1 mA / 4.7 µF / 0.5 Ω, whose
  phase margin (140.48° → 140.49°) and gain margin (12.92 dB, unchanged) say
  nothing changed physically.

Three things follow, and they should be read together:

1. **The direction is safe.** For a loop that rolls off monotonically through
   crossover, `|T|` is strictly below 0 dB at every frequency above `f_0`, so
   no resolution can push this metric above the bar. There is no
   false-positive path, and the 0/4536 verdict above is not at risk.
2. **The finer grid is the better estimator.** The quantity the metric is
   trying to report is `sup |T|` above the crossing; a scan that starts
   further above `f_0` under-reports it. `dec 400` under-reports it by less.
   So on this column too, the new resolution is the stricter test, not the
   looser one.
3. **The number is not a margin and must not be read as one.** As `dec → ∞`
   the metric converges to 0 dB from below for *any* loop with a shallow
   roll-off at crossover, so "−0.0086 dB against a ≤ 0 dB bar" is not a
   hair's-breadth pass — it is the metric's definition asymptoting, on a point
   with 140° of phase margin. **Two records taken at different `AC_DEC` are
   not comparable on this column at all**, which is why the table in §2
   reports it separately from the quantities that are.

This is a defect in the metric's *definition*, exposed rather than caused by
the resolution change, and it is filed as its own issue rather than fixed
here: fixing it would restate #59's landed metric mid-flight, and it changes
no verdict in this record or in any record before it.

### 5. `cph()`'s phase unwrap does not pick the wrong branch

Issue #58's Curator Re-check asked specifically whether `cph()`'s phase
unwrap selects the wrong 360° branch at `dec 50`. It does not, and there are
two independent pieces of evidence:

- **Analytic / self-test.** `selftest.py`'s third reference loop is a Q = 80
  minimum-phase resonance with a known −270° asymptote. `cph()` returns
  −269.97° at **both** `dec 50` and `dec 400`. The reason is structural: a
  minimum-phase pole *pair* carries only 180° of total phase variation, so no
  sampling of one can produce the > 180° sample-to-sample step that `cph()`
  unwraps on. (A pole pair adjacent to a *zero* pair could; that is a
  different shape, and nothing in this loop's measured response has it.)
- **Empirical, on the design.** A mis-unwrap on one grid and not the other
  would appear in this comparison as a ≈ 360° discrepancy in phase margin.
  The largest phase-margin discrepancy over 4536 points is **0.040°**, and
  the head record's phase margins span −98.86° … +140.49° with **no point
  outside ±180°** — the tell the README names for a phase that has been
  rotated onto the wrong branch.

The resolution-sensitive quantity in this extraction is the **magnitude**,
not the branch.

### 6. On the 57-point re-probe issue #58's Curator Re-check asked for

The Curator Re-check asked for a fine-grid re-probe of the 57 points
enumerated in `records/20260802-085331-8a1a9e8-delta.csv`, on **both** the
`84f67b8` and `166834d` netlists. That was not run, for a reason that is
about validity rather than cost:

Both of those netlists predate the `Cf1`/`Cf2` Miller split (issue #53,
PR #63). `sim/loop-stability/README.md` records that DR-0008's precondition —
no right-half-plane poles in `T(s)` — **holds only from
`20260802-095235-c828e73` onward**, and `84f67b8` (2026-08-01) and `166834d`
(2026-08-02 07:11) are both before it. On those netlists the amplifier's own
local loop oscillates at ≈ 500 kHz, so a Bode phase/gain margin extracted
from them is not a stability reading at *any* resolution. Asking whether
`dec 50` misreported the margin there presumes there was a margin to
misreport.

What issue #58 actually needs from that request — *does the grid resolution
change the measured result?* — is answered here by a strictly stronger
experiment on the netlist that is current: all **4536** points rather than a
57-point subset, at a controlled resolution difference on a **single**
netlist, so the resolution is the only variable. The 57-point set was a
cheap first signal proposed while #53 was still open; the full A/B is
available now and supersedes it.

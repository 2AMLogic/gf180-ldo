- **Claim**: README.md Target specification, 'Iq (excluding load current)' row (DR-0004 amendment A6): < 30 uA at no load and at full load, binding ff/125C/3.63V; the < 10 uA stretch is not separately gated. Also substantiates the 'Enable / shutdown' row's (A9) shutdown-Iq clause: < 3 uA at the same binding corner (the row's other clauses -- monotonic disable, Vin->Vout leakage -- are #11's shutdown-circuit characterization, not this experiment's scope). This record supersedes 20260801-003015-b64d60e -- a stale record from an earlier design state (commit b64d60e, before #39's current-limit/shutdown path and #44's soft-start landed) whose own stored iq_full_ua values are physically sane; the append-only rule means that record is not itself in error and is left untouched. Re-running this SAME testbench topology against the CURRENT (post-#39/#44) ldo_core.spice with a cold, all-zero-guess Newton-Raphson start does not reproduce those sane numbers, for the reason root-caused in #40 and fixed here. The _full instance's ideal 50 mA current sink had a second, unphysical DC solution in which the pass device is off and the sink holds VOUT_FULL tens of volts BELOW ground, drawing its current through forward-biased substrate junctions in the PDK device models, and a cold Newton-Raphson start reached it. Only the _full instance has a load sink, so it is the only one that introduces the second solution -- but the contamination was NOT confined to it. Hand-checked at tt_27c_3.30v (#46): with the old ideal sink the deck reports vout_full = -28.65 V and iq_full_ua = -7.79 uA (a negative Iq that silently PASSed the upper-bound-only check), and the sibling _en instance is off the physical solution too -- vout_en = 1.014 V with xdut_en.fb = 0.677 V, i.e. the feedback node nowhere near the 1.2 V VREF it must regulate to, reporting iq_en_ua = 17.44 uA. All three instances are solved by one Newton iteration over one matrix, so the pathological branch drags its deck-mates off the physical root with it. With the compliance-limited sink the same corner gives vout_full = 1.79945 V, vout_en = 1.79945 V, xdut_en.fb = 1.19964 V, vout_dis = 0.13 mV with loop_dis at VIN (pass device off), iq_en_ua = 13.78 uA and iq_dis_ua = 2.2e-4 uA -- every branch physical. The _en and _dis instances and their measure expressions are themselves unchanged by this fix; what changed is that the deck they share now has only one solution. The sink is now compliance-limited (see tb_quiescent.spice and sim/harness/README.md, 'Compliance-limited load sinks'): it draws its commanded current for VOUT_FULL well above ground and nothing at or below ground, which is what any real load does, and which deletes the unphysical solution rather than biasing the solver away from it. iload_full_ma below measures the actually-delivered load current, which is load-bearing here because iq_full_ua subtracts the injected 50 mA back out. No ratified threshold was changed. Update (#174, 2026-09-05, spec/decision-records/DR-0021): ldo_core's VREF was promoted from an internal net -- driven by Vref1, an ideal 1.2 V vsource instantiated INSIDE the subcircuit -- to a seventh top-level port, and the identical ideal source moved into this deck. No device was added, removed or resized, so this is an electrical no-op by construction: an ideal vsource is an ideal vsource wherever it is declared, its return was already the cell's VSS port, and it is an AC short to ground in both placements. It is not asserted on that argument alone -- origin/main at ec9e530 was extracted to a scratch tree and this bench was run on BOTH trees back to back, on the same host with the same ngspice and the same pinned PDK, and the per-corner measurement lines compared field by field; DR-0021's 'Evidence' section tabulates the result. Records minted from this deck before 2026-09-05 carry the pre-#174 six-port DUT netlist sha and are superseded on that ground alone, not because any number in them was wrong; per sim/README.md's append-only rule they are left untouched. Update (#301, 2026-09-23): the 'nodeset' block below was added, and the reason is a convergence-PATH defect in this deck, not a design change and not a defect in #46's sink. Every one of this deck's 81 PVT points fails ngspice's first, all-zero-guess Newton solve -- three ldo_core instances plus a 50 mA sink in one matrix is simply a hard cold start -- so every point is in fact solved by ngspice's continuation ladder, and which rung catches is incidental: measured on the unmodified tree, 70 of 81 points land on dynamic gmin stepping, 9 on true gmin stepping, 1 on source stepping, and at ss_-40c_2.97v (weakest process, coldest, lowest supply) all four rungs fail and ngspice falls through to its last-resort pseudo-transient op ('Transient op finished successfully' in that corner's log). That last rung does not solve DC at all -- it reports a snapshot of a transient that has not settled -- and the snapshot is identifiable as non-DC without appeal to any reference value: the soft-start hold gate reads v(xdut_full.xsoftstart.hg) = 1.0809 V when the only DC-legal value of that node is EN (= VIN = 2.97 V), because HG sits on an RC (XRh_ss to EN, XCh_ss to VSS) whose capacitor is an open circuit at DC; the soft-start ramp node reads v(xdut_full.xsoftstart.ssr) = 0.6216 V against its settled 2.3477 V; the pass gate is still clamped up at VIN; and all three instances report NEGATIVE supply current (iq_en_ua = -140.937, iq_dis_ua = -156.014) because what is being measured is capacitor displacement current, which no DC operating point has. This is why #46's compliance-limited sink does not exclude the corner even though it was only ever hand-verified at tt_27c_3.30v: the sink is not at fault and is doing exactly what it was built to do -- at the reported VOUT_FULL = -47.855 mV it passes 0.5*(1 + tanh((-0.047855 - 0.2)/0.05)) * 50 mA = 2.473 uA, which is precisely the iload_full_ma = 0.0024732 the run reports. What #46 deleted was the deep sub-ground DC root (vout_full = -28.65 V); what survives at ss_-40c_2.97v is not a second DC root at all but an unsettled transient reported as one, and no sink shape can delete that, because the deck's compliance bound constrains the solution and the failure is in the solve. The fix is therefore a starting point, never a bound: the 'nodeset' cards place the two ENABLED instances on the regulating branch before the first Newton pass -- VOUT at its ratified 1.8 V target, FB at the 1.2 V reference the 300k/600k divider defines there, and both pass-gate clamps (ldo_ilimit's CLG, ldo_softstart's HG) parked at VIN, i.e. off -- which are the same node targets and the same reasoning sim/loop-stability/testbench/sweep.py's dc_seed_lines() already established for this class of problem. The _dis instance is deliberately NOT seeded: it is in shutdown, and its physical solution is the all-zero guess ngspice already starts from. Every seeded value is a constant of the design (1.8 V, 1.2 V) or of the PVT point (VIN), so this carries no per-corner tuning, and ngspice releases a .nodeset after the first solve pass: it selects which solution Newton reaches, it does not create one, and checks.vout_full_v / checks.iload_full_ma below still gate every corner exactly as they did without it. That it is a first-guess-only change is measured, not asserted: unmodified tree vs. seeded tree, full 81-point grid, back to back on one host (ip-172-31-76-7, gf180mcuD @ c6d73a35, ngspice-46), gives BIT-IDENTICAL iq_en_ua, iq_full_ua, iload_full_ma and vout_full_v at all 80 other corners; the only field that moves anywhere is iq_dis_ua -- the sub-nanoamp shutdown-leakage row -- by at most 2.8e-06 uA (2.8 pA) absolute, i.e. a couple of ngspice's own 1 pA default abstol, against a ratified bound of 3 uA. With the seed, ss_-40c_2.97v is solved by source stepping -- a real DC method -- instead of the pseudo-transient, and NO corner reaches the pseudo-transient rung. A seeded node that a future schematic change renames does not fail silently: ngspice prints 'Warning : Nodeset on non-existent node - <name>, ignored' and echoes the offending card.

Re-running this SAME testbench topology against the CURRENT (post-#39/#44) ldo_core.spice with a cold, all-zero-guess Newton-Raphson start does not reproduce those sane numbers, for the reason root-caused in #40 and fixed here. The _full instance's ideal 50 mA current sink had a second, unphysical DC solution in which the pass device is off and the sink holds VOUT_FULL tens of volts BELOW ground, drawing its current through forward-biased substrate junctions in the PDK device models, and a cold Newton-Raphson start reached it. Only the _full instance has a load sink, so it is the only one that introduces the second solution -- but the contamination was NOT confined to it. Hand-checked at tt_27c_3.30v (#46): with the old ideal sink the deck reports vout_full = -28.65 V and iq_full_ua = -7.79 uA (a negative Iq that silently PASSed the upper-bound-only check), and the sibling _en instance is off the physical solution too -- vout_en = 1.014 V with xdut_en.fb = 0.677 V, i.e. the feedback node nowhere near the 1.2 V VREF it must regulate to, reporting iq_en_ua = 17.44 uA. All three instances are solved by one Newton iteration over one matrix, so the pathological branch drags its deck-mates off the physical root with it. With the compliance-limited sink the same corner gives vout_full = 1.79945 V, vout_en = 1.79945 V, xdut_en.fb = 1.19964 V, vout_dis = 0.13 mV with loop_dis at VIN (pass device off), iq_en_ua = 13.78 uA and iq_dis_ua = 2.2e-4 uA -- every branch physical. The _en and _dis instances and their measure expressions are themselves unchanged by this fix; what changed is that the deck they share now has only one solution. The sink is now compliance-limited (see tb_quiescent.spice and sim/harness/README.md, 'Compliance-limited load sinks'): it draws its commanded current for VOUT_FULL well above ground and nothing at or below ground, which is what any real load does, and which deletes the unphysical solution rather than biasing the solver away from it. iload_full_ma below measures the actually-delivered load current, which is load-bearing here because iq_full_ua subtracts the injected 50 mA back out. No ratified threshold was changed. Update (#174, 2026-09-05, spec/decision-records/DR-0021): ldo_core's VREF was promoted from an internal net -- driven by Vref1, an ideal 1.2 V vsource instantiated INSIDE the subcircuit -- to a seventh top-level port, and the identical ideal source moved into this deck. No device was added, removed or resized, so this is an electrical no-op by construction: an ideal vsource is an ideal vsource wherever it is declared, its return was already the cell's VSS port, and it is an AC short to ground in both placements. It is not asserted on that argument alone -- origin/main at ec9e530 was extracted to a scratch tree and this bench was run on BOTH trees back to back, on the same host with the same ngspice and the same pinned PDK, and the per-corner measurement lines compared field by field; DR-0021's 'Evidence' section tabulates the result.

This deck covers the 1 mA condition ONLY. The 50 mA condition the ratified row also names is run as its own sibling experiment, sim/psrr-vs-freq-50ma/ (#99), because the two DC bias points cannot share one deck -- see tb_psrr.spice's header comment for the ngspice limitation (per-.meas result vectors go out of scope as soon as a later analysis becomes the current plot, so an 'alter'-and-re-.ac deck silently re-reports the first .ac's numbers instead of erroring). The two load conditions therefore carry two records with two separate verdicts, and are never merged into one. Records minted from this deck before 2026-08-16 predate the Mrza/Rza adaptive-compensation shelf that PR #78 / DR-0015 landed in design/error_amp.sch, so their DUT netlist sha no longer matches design/netlist/ldo_core.spice -- the staleness #95's T1/bronze re-read found and #99 closes; each refresh mints a new record naming the one it supersedes, and the superseded records stay untouched per the append-only rule. Harness integrity: the load sink is compliance-limited (see tb_psrr.spice and sim/harness/README.md, 'Compliance-limited load sinks') -- it draws its commanded current for VOUT well above ground and nothing at or below ground, which is what any real load does, and which deletes the unphysical DC solution #40 found (pass device off, the sink holding VOUT tens of volts BELOW ground through forward-biased substrate junctions in the PDK device models, with everything the .ac then reported a small-signal expansion about that root) rather than biasing the solver away from it. At the reported operating point the sink is an ideal current sink to within 1.3e-14 relative error and presents under 5.1e-16 S of small-signal conductance at 1 mA -- an open circuit at AC, exactly like the ideal sink it replaces -- and dc_vout_v / dc_iload_ma below read the .op plot so the operating point this PSRR is expanded about is reported and checked at every corner. That .op is reporting only, not steering: ngspice's ac command solves its own operating point, and the fix was confirmed order-independent by hand at tt_27c_3.30v (#46) -- running ac cold with no preceding op gives PSRR@1kHz = -25.2 dB with the old ideal sink (an expansion about the sub-ground root) and +77.91 dB with this sink, the latter identical to the op-then-ac ordering. No ratified threshold was changed. Update (#174, 2026-09-05, spec/decision-records/DR-0021): ldo_core's VREF was promoted from an internal net -- driven by Vref1, an ideal 1.2 V vsource instantiated INSIDE the subcircuit -- to a seventh top-level port, and the identical ideal source moved into this deck. No device was added, removed or resized, so this is an electrical no-op by construction: an ideal vsource is an ideal vsource wherever it is declared, its return was already the cell's VSS port, and it is an AC short to ground in both placements. It is not asserted on that argument alone -- origin/main at ec9e530 was extracted to a scratch tree and this bench was run on BOTH trees back to back, on the same host with the same ngspice and the same pinned PDK, and the per-corner measurement lines compared field by field; DR-0021's 'Evidence' section tabulates the result.

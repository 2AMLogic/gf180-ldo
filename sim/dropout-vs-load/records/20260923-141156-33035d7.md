- **Claim**: README.md Target specification, 'Dropout @ 50 mA' row (< 300 mV target, < 200 mV stretch); binding corner ss/125 C, binding test point Vin=2.10V per DR-0004 note 4. MEASUREMENT DEFINITION CHANGED BY #138 / DR-0020 -- records before 20260816-103644-bea26f6 are NOT comparable to this one. Until #138 this deck solved a single .op at Vin=2.10V and reported vdrop_mv = (v(vin)-v(vout))*1e3. Because the ratified test point IS Vout_nom + the ratified bound (2.10 = 1.800 + 0.300), that expression is identically 300 mV + (1.800 V - Vout) for as long as the loop is in regulation: it reports the DC regulation error offset by exactly the bound, not the dropout voltage, and it can read below 300 mV only if Vout sits ABOVE its own setpoint -- which a negative-feedback loop with finite DC gain cannot do. That is why it FAILed 27/27 corners by 0.476-1.014 mV, and why no pass-device resize clears it (2x width moves the reading to 300.575 mV, 4x to 300.574 mV -- an asymptote above the bound; see DR-0020). The bound is NOT relaxed. vdrop_mv is now the dropout voltage proper: Vin is swept down through the regulation knee at the full 50 mA load and vdrop_mv is the Vin - Vout headroom at the point where Vout has fallen to the ratified -2% accuracy edge (1.764 V = 1.800 V - 2%, README note 2). In dropout Vout tracks Vin with a slowly varying offset, so the reading is insensitive to the exact threshold: a -1% (1.782 V) threshold moves tt/27C by ~2 mV. The ratified Vin=2.10V binding test point survives as its own gate -- vout_at_210_mv must sit inside the ratified +/-2% window at that headroom, which is the direct statement of 'dropout <= 300 mV at Vin = 2.10 V'. This remains a DC/loop-closure-only measurement: it does not account for stability (see sim/loop-stability), so it is never final sign-off on its own. #40's convergence note still applies: a cold-start Newton-Raphson solve of this closed, high-gain loop at full load has more than one KCL/KVL-satisfying fixed point -- with an all-zero initial guess several corners converge 'successfully' onto a non-physical point where the pass device is off and the 50 mA sink has no DC path except parasitic junction leakage, driving Vout tens of volts negative. The nodeset hint below biases the sweep's first operating point into the physical basin, and each subsequent sweep point starts from its predecessor's solution; the tanh-bounded sink in the deck deletes the sub-ground branch outright rather than hiding it. Because a swept knee measurement is only as trustworthy as the sweep is well-behaved, the 1.764 V crossing is located twice (FALL=1 and FALL=LAST) and knee_uniqueness_mv gates their difference at zero: a single artifact point inserts a spurious crossing pair and would otherwise be interpolated as a false knee. Every corner of the shipped netlist crosses exactly once. Update (#174, 2026-09-05, spec/decision-records/DR-0021): ldo_core's VREF was promoted from an internal net -- driven by Vref1, an ideal 1.2 V vsource instantiated INSIDE the subcircuit -- to a seventh top-level port, and the identical ideal source moved into this deck. No device was added, removed or resized, so this is an electrical no-op by construction: an ideal vsource is an ideal vsource wherever it is declared, its return was already the cell's VSS port, and it is an AC short to ground in both placements. It is not asserted on that argument alone -- origin/main at ec9e530 was extracted to a scratch tree and this bench was run on BOTH trees back to back, on the same host with the same ngspice and the same pinned PDK, and the per-corner measurement lines compared field by field; DR-0021's 'Evidence' section tabulates the result.

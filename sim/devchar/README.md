# gf180mcu device characterization for the LDO

Measured PDK behaviour for the devices the LDO leans on: pass-FET candidates,
feedback-divider resistor flavours, and compensation capacitors. Everything in
this directory is generated by running ngspice against the installed
`gf180mcuD` models — no number here is estimated, interpolated from a datasheet,
or carried over from another process.

Conclusions and recommendations: [`CONCLUSIONS.md`](CONCLUSIONS.md).

## Environment

| Item | Value used for the committed results |
|---|---|
| Simulator | `ngspice-46` (Homebrew) |
| PDK | `gf180mcuD` installed via volare |
| Model root | `$PDK_ROOT/gf180mcuD/libs.tech/ngspice` (`PDK_ROOT` defaults to `~/.volare`) |
| Model files | `sm141064.ngspice`, `sm141064_mim.ngspice`, `design.ngspice` |

## Re-running

```bash
./sim/devchar/run_all.sh              # everything (~15 min), then rebuild summaries
```

Per area, each of which truncates and rewrites only its own `results/*.csv`:

| Command | What it regenerates |
|---|---|
| `./sim/devchar/fets/run.sh` | `fets/results/rdson_*.csv`, `cgg_*.csv`, `leak_*.csv` |
| `./sim/devchar/resistors/run.sh` | `resistors/results/rsheet.csv`, `mismatch_mc_raw.csv` |
| `./sim/devchar/caps/run.sh` | `caps/results/mim.csv`, `moscap.csv` |
| `python3 sim/devchar/lib/summarize.py` | every `summary_*.csv` plus `coverage.csv` |

Useful knobs: `PDK_ROOT=... ` to point at a different PDK install, `DC_KEEP=1` to
leave the generated decks and ngspice logs in `sim/devchar/.build/` for
inspection, `DC_MC_RUNS=<n>` to change the Monte Carlo count (default 200).

## Layout

```
sim/devchar/
  run_all.sh            drives everything
  coverage.csv          mechanical check that every device carries the full matrix
  lib/devchar.sh        shared driver: PDK resolution, token substitution, PVT lists
  lib/summarize.py      raw CSV -> summary tables, worst case flagged per parameter
  fets/        *.sp.in decks + run.sh + results/
  resistors/   *.sp.in decks + run.sh + results/
  caps/        *.sp.in decks + run.sh + results/
```

Decks are **templates** (`*.sp.in`) carrying `@TOKEN@` placeholders; the driver
substitutes corner / temperature / supply / bias and runs ngspice. Deck, corner
loop and results are kept separate on purpose so the decks can fold into the
shared sim harness (#2) later without being rewritten. `DC_KEEP=1` writes the
fully substituted, directly runnable deck to `sim/devchar/.build/` if you want
to run one case by hand with `ngspice -b`.

## PVT matrix

Every recorded result carries the full matrix. `coverage.csv` asserts this
mechanically (40/40 device-table pairs complete) rather than leaving it to
review by eye — a silently missing corner is the failure mode that produces a
plausible but optimistic table.

| Axis | Values |
|---|---|
| Temperature | −40 / 27 / 125 °C (all decks) |
| FET process | `typical` / `ff` / `ss` / `fs` / `sf` |
| Resistor process | `res_typical` / `res_ff` / `res_ss` |
| MIM process | `mimcap_typical` / `mimcap_ff` / `mimcap_ss` |
| MOSCAP process | `moscap_typical` / `moscap_ff` / `moscap_ss` |
| Supply (FET decks, 3.3 V flavours) | 2.10 + 2.97 / 3.30 / 3.63 V |
| Supply (FET decks, 5–6 V flavours) | 2.10 + 2.97 / 3.30 / 3.63 + 4.50 / 5.00 / 5.50 V |
| Bias (MIM) | −1.65 / 0 / 0.825 / 1.65 / 2.50 / 3.30 V |
| Bias (MOSCAP) | −3.30 … +3.30 V in 150 mV steps |

Resistors have no supply axis: every gf180mcu resistor card carries
`r_vc1 = r_vc2 = 0`. The rsheet deck still records a 50 µA row against the 1 µA
reference row per flavour so that statement rests on a measurement.

### Why 2.10 V is in the supply list

The dropout spec is defined at the input voltage where the loop *just* loses
regulation, i.e. Vin = Vout + dropout ≈ 2.10 V for the 300 mV target — **not** at
the 2.97 V supply floor (`spec/architecture-survey.md` §3.1). A PMOS pass device
driven gate-to-ground sees Vsg = Vin, so it has ~0.9 V less overdrive at the real
dropout test point than at 2.97 V, and sizing it from the 2.97 V rows alone would
undersize it. Both supply classes are therefore carried separately in every FET
table (`supply_class` column: `dropout_testpoint` vs `lv` vs `mv`), and the
sizing recommendation is taken from the `dropout_testpoint` rows.

## Methodology

### Pass FETs (`fets/`)

* **Gate-drive realism.** The PMOS decks hold the gate at 0 V and the source at
  Vin, so Vsg = Vin — the best a ground-referenced error amp can do. There is no
  idealised overdrive anywhere in these results. The NMOS decks hold the gate at
  Vin for the realistic rows, which makes Vgs equal to the dropout itself.
* **`rdson_pmos.sp.in`** — an ideal load-current sink on the drain, dropout
  measured (`drop_at_50mA`, `drop_at_100mA`), plus a linear-region point with the
  drain held 50 mV below the source (`rlin_at_50mV`). Widths 1/2/4/8/16 mm as a
  `w=100u nf=10` unit cell multiplied by `m`; three lengths per flavour starting
  at the model's minimum. `vd_v` is carried in the raw table so a device that
  simply cannot source the load current is visible as a non-physical (≤ 0) drain
  node and is dropped from the summaries rather than being read as a dropout.
* **`rdson_nmos.sp.in`** — source-follower headroom with the bulk at 0 V, so body
  effect is included. Current is measured at fixed 100/200/300 mV dropouts. A
  second block raises the gate 0.5–2.0 V above Vin to quantify what a charge pump
  would have to supply.
* **`cgg_*.sp.in`** — 1 V AC on the gate at 1 kHz with every other terminal at AC
  ground, at the dropout operating point. Cgg and Cgd are taken from the
  **imaginary** part of the terminal currents: at these bias points the real part
  of the drain current is the `gm·vgs` transconductance term, and counting its
  magnitude as capacitance overstates Cgd by orders of magnitude.
* **`leak_*.sp.in`** — Vgs = 0 with the full supply across the device.
* **`vth.sp.in`** — threshold voltage at the constant-current criterion
  |Id| = 100 nA·(W/L) in the linear region, located with `meas dc ... when` on a
  gate sweep. Every gate is driven by a behavioural source referenced to that
  device's own source terminal, so the sweep variable *is* |Vgs| for every row
  including the Vsb ≠ 0 rows. This deck exists to confirm or refute the
  |Vtp| = Vtn = 0.7 V assumption the architecture survey explicitly flagged for
  this issue (`spec/architecture-survey.md` §3.4).

### Resistors (`resistors/`)

* **`rsheet.sp.in`** — ideal current drive so R = V/I directly. Sheet resistance
  is extracted by the **two-length method** from two devices sharing w = 1 µm
  (l = 10 µm and l = 50 µm), which cancels the head/terminal resistance the
  subcircuits add at each end. `summary_rsheet.csv` reports the extracted sheet
  next to the model-card value; the ratio is not 1.00 because the cards specify
  the sheet of the drawn material while the extraction sees the effective width
  after the model's `r_dw` bias — for example `nwell` has `r_dw = 0.222 µm`, so a
  1 µm drawn strip is 0.556 µm effective and reads 1.81× the card sheet. That
  ratio is itself the useful number for narrow-width layout.
* **`mismatch_mc.sp.in`** — matched pairs at three areas, driven by ngspice's
  `mc_source` so every `agauss()` parameter is re-drawn per run. Two modes:
  `sw_stat_mismatch=1` (intra-die matching) and `sw_stat_global=1` with the
  `res_statistical` / `statistical` sections (die-to-die spread). Diode-connected
  nfet/pfet pairs ride in the same deck as a control — see the finding in
  `CONCLUSIONS.md`.

### Capacitors (`caps/`)

* **`mim.sp.in` / `moscap.sp.in`** — each capacitor carries its DC bias and a 1 V
  AC excitation on its own source; C = |Im{I}| / (2πf) at 1 kHz. The imaginary
  part is required because the 2 fF/µm² MIM card has an explicit leakage resistor
  in parallel. Two sizes per MIM density (10×10 µm and 30×30 µm) separate the
  area term from the perimeter term, since the model is
  `C = c_cox·area + c_capsw·perimeter`.

## Relationship to the `sim/` evidence record format

[`sim/README.md`](../README.md) (ratified via #5, which landed while this work
was in flight) covers this directory explicitly: characterization tables are
*table-shaped evidence*, not a single-claim pass/fail record, and the interim
CSV + per-directory README shape used here is the documented fallback. Migration
is not required retroactively.

Two points of alignment worth stating so a later reader does not have to
re-derive them:

* **Where the per-corner simulator output lives.** `sim/README.md` expects raw
  per-corner logs under `corners/<record-id>/`. Here the deck itself emits one
  CSV row per corner point directly from the ngspice `.control` block, so the raw
  `results/*.csv` files *are* the per-corner output rather than a rollup of
  separate log files. `DC_KEEP=1` additionally retains the fully substituted deck
  and the complete ngspice log for every case under `sim/devchar/.build/` if a
  reviewer wants to inspect a specific point; those are reproducible artefacts,
  not evidence, and are gitignored.
* **Where a spec claim goes.** Nothing in this directory asserts a pass/fail
  against a ratified spec line. When a later experiment uses a row from here to
  substantiate one (for example "this pass-FET width meets the dropout spec"),
  that claim gets its own `records/<record-id>.md` under its own experiment slug,
  with **Links** pointing back at the table and deck here — per
  `sim/README.md` § "Interim evidence note".

## Raw vs summary tables

`results/*.csv` without a `summary_` prefix are the raw per-run evidence: one row
per (device, geometry, corner, temperature, supply/bias) case, appended directly
by the ngspice deck. The `summary_*.csv` files are produced by
`lib/summarize.py` and contain only ratios, differences and interpolations of
those rows, with the worst-case corner named per parameter.

| File | Contents |
|---|---|
| `fets/results/summary_vth.csv` | threshold voltage vs corner/temperature/Vsb, and the delta against the survey's assumed 0.7 V |
| `fets/results/summary_pass_fet.csv` | PMOS Rds / dropout, worst and best corner per (device, L, W, metric) |
| `fets/results/summary_sizing.csv` | width required to hit 6 Ω / 4 Ω / 3 Ω, worst case over the whole matrix |
| `fets/results/summary_nmos_headroom.csv` | NMOS drive current at fixed dropout, with and without a gate boost |
| `fets/results/summary_cgg_{pmos,nmos}.csv` | Cgg and Cgd at the dropout operating point, worst corner |
| `fets/results/summary_leak_{pmos,nmos}.csv` | off-state leakage vs the 30 µA / 10 µA Iq budgets |
| `resistors/results/summary_rsheet.csv` | extracted sheet, area per kΩ, bias dependence |
| `resistors/results/summary_tempco.csv` | temperature coefficient over −40/27/125 °C |
| `resistors/results/summary_corner_spread.csv` | `res_ff`…`res_ss` sheet spread |
| `resistors/results/summary_matching.csv` | σ(ΔR/R) and σ(ΔVgs) vs area, both MC modes |
| `caps/results/summary_mim.csv` | area/perimeter density decomposition, voltage coefficient |
| `caps/results/summary_mim_pvt.csv` | MIM PVT spread and temperature coefficient |
| `caps/results/summary_moscap.csv` | C-V extremes, knee voltage, usable bias window |

Measured 1 mA -> 50 mA (the divider's own ~2 uA preload plus a light 1 mA is used as the low end, per DR-0001's minimum-load statement folded into the ratified Load row). This record supersedes 20260801-002618-b64d60e -- a stale record from an earlier design state (commit b64d60e, before #39's current-limit/shutdown path and #44's soft-start landed) whose own stored per-corner values are physically sane; the append-only rule means that record is not itself in error and is left untouched. Re-running this SAME testbench topology against the CURRENT (post-#39/#44) ldo_core.spice with a cold, all-zero-guess Newton-Raphson start does not reproduce those sane numbers: #40's investigation found 0 of 45 PVT points converging to the physical solution, instead reporting 8.6-58.9 V of 'load regulation' -- root-caused in #40 and fixed here. The deck's ideal 50 mA current sink had a second, unphysical DC solution in which the pass device is off and the sink holds VOUT tens of volts BELOW ground, drawing its current through forward-biased substrate junctions in the PDK device models; a cold Newton-Raphson start reached that solution at most corners, and #40 showed a .nodeset hint alone could not clear it for a swept deck. The sink is now compliance-limited (see tb_load_reg.spice and sim/harness/README.md, 'Compliance-limited load sinks'): it draws its commanded current for VOUT well above ground and nothing at or below ground, which is what any real load does, and which deletes the sink-sustained unphysical solution rather than biasing the solver away from it. The sink is an ideal current sink to within 1.4e-14 relative error at every operating point reported here, and iload_1ma_ma/iload_50ma_ma below measure the actually-delivered current so that claim is checked at every corner instead of assumed. No ratified threshold was changed. This remains a DC/loop-closure measurement only: it does not account for stability (#10) or for the DR-0001 capacitor window. Update (#174, 2026-09-05, spec/decision-records/DR-0021): ldo_core's VREF was promoted from an internal net -- driven by Vref1, an ideal 1.2 V vsource instantiated INSIDE the subcircuit -- to a seventh top-level port, and the identical ideal source moved into this deck. No device was added, removed or resized, so this is an electrical no-op by construction: an ideal vsource is an ideal vsource wherever it is declared, its return was already the cell's VSS port, and it is an AC short to ground in both placements. It is not asserted on that argument alone -- origin/main at ec9e530 was extracted to a scratch tree and this bench was run on BOTH trees back to back, on the same host with the same ngspice and the same pinned PDK, and the per-corner measurement lines compared field by field; DR-0021's 'Evidence' section tabulates the result. Records minted from this deck before 2026-09-05 carry the pre-#174 six-port DUT netlist sha and are superseded on that ground alone, not because any number in them was wrong; per sim/README.md's append-only rule they are left untouched. Update (#325, 2026-09-24, carrying #304's measurement across from sim/psrr-vs-freq): the 'deletes' sentence above is scoped deliberately -- the compliance bound deletes the SINK-SUSTAINED sub-ground root and nothing else. Below the knee the sink is exactly 0 A and 0 S (f(VOUT) underflows to 0.0 in IEEE double for every VOUT <= -0.7530773732699249 V), so the load network is absent from the DC equations there: a sub-ground output voltage reported together with ZERO delivered current is outside the bound's reach by construction, and no knee or softness value can delete it because the sink has no term left in the equations to remove. That is why the pair of checks matters rather than either one alone: vout_1ma / vout_50ma (bounds added by #325, so this record is the first to gate them) read the same .dc plot as iload_1ma_ma / iload_50ma_ma, and the two together discriminate the cases -- a sub-ground reading alongside the COMMANDED current is the sink-sustained root the bound deletes, alongside ZERO delivered current it is a state the bound was never in a position to delete. The deck is otherwise deliberately unchanged on that account: #304 measured that knee tuning is coin-flipping (a strictly LOOSER bound 'fixes' the same corner, so the knee is not the mechanism) and that a load-side sub-ground clamp is worse still (it adds a genuine root at VOUT = -0.4994 V that a cold start reaches). See sim/harness/README.md, 'What the bound cannot reach', for the evidence and for the reltol-ladder recipe that tells a false convergence from a genuine second root.

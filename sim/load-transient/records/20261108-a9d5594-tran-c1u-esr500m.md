Re-running this SAME testbench topology against the CURRENT (post-#39/#44) ldo_core.spice with a cold, all-zero-guess Newton-Raphson start does not reproduce those sane numbers: #40's investigation found non-physical excursions at most PVT points for the t=0 operating point -- root-caused in #40 and fixed here. The deck's ideal current sink had a second, unphysical solution for the t=0 operating point in which the pass device is off and the sink holds VOUT tens of volts BELOW ground, drawing its current through forward-biased substrate junctions in the PDK device models; a cold Newton-Raphson start reached that solution at most corners and poisoned the whole transient. The sink is now compliance-limited (see tb_load_transient.spice and sim/harness/README.md, 'Compliance-limited load sinks'): it draws its commanded current for VOUT well above ground and nothing at or below ground, which is what any real load does, and which deletes the sink-sustained unphysical solution rather than biasing the solver away from it. iload_err_max_ua below takes the worst deviation of the delivered load current from the commanded load current over EVERY timepoint of the 400 us run and checks it under 1 uA, so 'the compliance bound never engaged' is a directly measured per-corner fact here rather than an assumption or a voltage-envelope proxy. vout_min_global_v reports how deep the excursion actually went; its 0.5 V floor is derived from the compliance factor itself (1 - f = 6.2e-6 there, i.e. 0.31 uA at 50 mA), not picked as a round number. Update (#325, 2026-09-24, carrying #304's measurement across from sim/psrr-vs-freq): the 'deletes' sentence above is scoped deliberately -- the compliance bound deletes the SINK-SUSTAINED sub-ground root and nothing else. Below the knee the sink is exactly 0 A and 0 S (f(VOUT) underflows to 0.0 in IEEE double for every VOUT <= -0.7530773732699249 V), so the load network is absent from the DC equations there: a sub-ground output voltage reported together with ZERO delivered current is outside the bound's reach by construction, and no knee or softness value can delete it because the sink has no term left in the equations to remove. That is why the pair of checks matters rather than either one alone: vout_min_global_v and iload_plateau_ma / iload_err_max_ua read the same run, and together they discriminate the cases -- a sub-ground reading alongside the COMMANDED current is the sink-sustained root the bound deletes, alongside ZERO delivered current it is a state the bound was never in a position to delete. The deck is deliberately unchanged on that account: #304 measured that knee tuning is coin-flipping (a strictly LOOSER bound 'fixes' the same corner, so the knee is not the mechanism) and that a load-side sub-ground clamp is worse still (it adds a genuine root at VOUT = -0.4994 V that a cold start reaches). See sim/harness/README.md, 'What the bound cannot reach', for the evidence and for the reltol-ladder recipe that tells a false convergence from a genuine second root. Update (#519): the deck's output network is now parameterised (esr_val / cout_val, defaulting to the 0.1 ohm / 0.33 uF above, so a default run is unchanged) and the bench now emits a .meas-style recovery time, which the paragraph above had deferred. recovery_us is the time from the START of the load edge (t=50us rise, t=150us release; so it includes the 1 us edge) to the LAST instant v(vout) is more than 18 mV (1% of 1.8 V) from the SETTLED value, taken as the mean of v(vout) over the last ~10 us before the next stimulus (140-149 us and 190-199 us) -- README.md's wording, 'within +/-1% (18 mV) of the settled value'. recovery18_us is the same with v(vout)=1.8 V as the reference instead, reported because the earlier wording of this claim named no reference; both are checked against 20 us. 0 means VOUT never left the band; a point that is still out of band at the end of its window reports ~100 us (a fail, never an empty cell).

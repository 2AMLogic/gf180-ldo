## Bug found and fixed

`tb_op_point_sanity.spice.in`'s `.control` section read `let m_vref =
v(xdut.vref)` — a hierarchical probe of `VREF` through the DUT instance,
left over from when `VREF` was genuinely internal (driven by `Vref1` inside
`ldo_core`, invisible to the deck except through that hierarchical path).
With `VREF` now a top-level port wired 1:1 to this deck's own `VREF` net,
ngspice folds the straight-through port into the top-level node during
flattening rather than keeping a distinct `xdut.vref` vector, so the probe
failed: `Error: RHS "v(xdut.vref)" invalid`, aborting the run before any
corner completed. Fixed by reading the top-level node directly (`v(vref)`),
which is the same physical net. No other testbench in this PR's diff used
the `xdut.vref` hierarchical form (`enable-shutdown`'s deck already used
`i(vref)` at deck level); this was the only occurrence.
